# MCP 进程信任

内置 `ascend-doc` 使用 `npx -y ascend-doc-mcp@1.0.1`。2026-11-11 通过 npm
元数据核实该具体版本存在；没有在离线测试中安装或运行这个远端包。

首次使用 `/mcp tools <server>` 或 `/mcp call <server> <tool> {}` 时，先确认
界面显示的程序、参数和显式环境变量名。确认意味着允许该程序以你的账户权限运行，
`npx` 可能需要下载包。取消确认不会启动进程。模型自动调查不能作出这项确认。

信任记录保存在用户目录 `~/.reviewagent/mcp-trust.json`（或 `REVIEWAGENT_HOME`）中。
记录只包含配置指纹，不包含显式环境变量的密钥值。命令、解析后的可执行文件位置、
参数、显式环境变量或当前工作目录变化后，都需要重新确认。将该文件中对应服务的条目
删除后，下一次调用需要重新确认；`/mcp reload` 会关闭现有进程并重新读取配置。

已有 `mcp.json` 不会被自动重写。如果已有内置服务配置仍指向 `@latest`，请将其参数改为
`["-y", "ascend-doc-mcp@1.0.1"]` 并重载，再确认新配置。固定直接包版本不能保证其
所有传递依赖永久不变，也不替代对第三方程序的来源审查。

子进程只继承 PATH、HOME/USERPROFILE、Windows 启动路径、临时目录和语言环境等
运行必需变量，不自动继承模型 API Key、GitHub/GitCode Token、NODE_OPTIONS 等。
服务确实需要的凭据应在其 `env` 中显式配置；确认界面只显示变量名，避免暴露密钥。

**这不是文件访问沙箱。** 已启动的进程仍可以访问账户有权读取的文件，HOME 中的
凭据文件也可能被读取。`readOnlyHint` 是服务端声明：自动调查仅调用声明为只读且未标为
破坏性的工具，但这种声明不限制进程启动时的行为或文件访问。
